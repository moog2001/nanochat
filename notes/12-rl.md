# 12 — RL: learning from rewards instead of examples (`scripts/chat_rl.py`)

> Companion experiment: [experiments/rl_toy.py](experiments/rl_toy.py)
> (`.venv\Scripts\python.exe -m notes.experiments.rl_toy`; no model or data needed). Code at commit `92d63d4`.
> RL itself was not run here: it needs an SFT model. This guide is from reading the code, plus the toy that
> uses the same update rule.

SFT copies reference answers token by token. RL instead lets the model **try**, checks only whether the
**final answer** is right, and makes the attempts that worked more likely. No one has to write the reasoning
steps. nanochat does this on GSM8K math problems, where correctness can be checked automatically.

## 1. One RL step (`chat_rl.py:86-146`, `222-305`)

For each of 16 questions per step (`--examples-per-step`):

1. **Prompt** with `render_for_completion` (the question + `<|assistant_start|>`, see [05](05-tokenizer.md)).
2. **Sample 16 answers** (`--num-samples`) with the Engine at temperature 1.0, top-k 50, up to 256 tokens.
   Tool calls work as at chat time ([09](09-inference.md)).
3. **Reward** each answer: 1 if the number after `####` matches the reference, else 0
   (`GSM8K.reward` = `evaluate`, `tasks/gsm8k.py:109-116`).
4. **Advantage** = reward − (mean reward of the 16 answers to the *same* question) (L142–144).
5. **Loss** = −Σ over generated tokens of `log p(token) × advantage`, divided by the number of valid tokens
   (L264–272). Prompt tokens and forced calculator outputs are masked out (L136–140).
6. One optimizer step for all 16 × 16 = 256 sequences.

The script's docstring (L1–17) is upfront that it calls this "GRPO" but simplifies it to something close to
plain **REINFORCE**:
- **No KL penalty** toward a reference model.
- **No PPO ratio/clipping.** Every sample comes from the current model ("on-policy"), so they aren't needed.
- **Token-level normalization** (DAPO style): long and short answers contribute per token.
- Advantage is `r − mean`, not z-scored by the standard deviation.

Other settings: learning rate starts at 5% of base (`--init-lr-frac 0.05`) and decays linearly to 0. Weight
decay 0. One epoch over GSM8K's 7,473 problems is 467 steps. Every 60 steps it measures pass@1…8 on 400 test
problems. Checkpoints go to `chatrl_checkpoints/` without optimizer state.

## 2. Why "reward − mean"? (experiment part 3)

```
reward 1 -> advantage +0.50 applied to each of its 5 tokens
reward 0 -> advantage -0.50 applied to each of its 9 tokens
reward 0 -> advantage -0.50 applied to each of its 7 tokens
reward 1 -> advantage +0.50 applied to each of its 4 tokens
loss = -sum(logp_t * advantage) / 25 valid tokens
```

- Answers **better than the group average** get pushed up, and **worse** ones get pushed down. The other
  answers to the *same question* act as the baseline, so no separate "value model" is needed. That's the core
  idea of GRPO.
- **Every token of an answer gets the same credit.** RL doesn't know *which* step of the reasoning was good,
  only that the whole attempt worked. Across many samples, good steps show up more often in successful attempts.

## 3. The update rule on a toy problem (experiment parts 1–2)

A "policy" over 4 answers, trained with exactly the recipe above (16 samples, 0/1 reward, `r − mean`
advantage):

```
1) uniform start, P(correct) = 0.25
  step  0: P(correct) 0.250 |  4/16 samples correct | advantages [-0.25, 0.75]
  step 10: P(correct) 0.607 | 10/16 samples correct | advantages [-0.625, 0.375]
  step 20: P(correct) 0.841 | 14/16 samples correct | advantages [-0.875, 0.125]
  step 39: P(correct) 0.940 | 15/16 samples correct | advantages [-0.938, 0.062]

2) P(correct) = 0.0008 at start: almost never sampled
  step  0: P(correct) 0.001 | 0/16 samples correct | advantages [0.0]
  ...
  step 39: P(correct) 0.001 | 0/16 samples correct | advantages [0.0]
```

Two lessons:

1. **RL sharpens what the model can already sometimes do.** In case 1 a 25% success rate becomes 94%.
2. **RL can't find what the model never tries.** In case 2 every group gets the same reward (all zero), every
   advantage is 0, and there's no gradient at all. This is why the pipeline goes **pretrain → SFT → RL**: SFT
   on GSM8K solutions ([10](10-sft.md)) gets the model to *sometimes* produce correctly formatted, correct
   answers, and RL has something to reinforce.

As a corollary, questions where all 16 samples are right also teach nothing. Learning comes from questions at the edge
of the model's ability.

## 4. pass@k (`chat_rl.py:225-243`)

During RL eval, each test problem gets 8 samples at temperature 1.0. **pass@k** = the fraction of problems where
at least one of the first k samples is correct. pass@1 is "how often is a single try right". pass@8 is "can it
solve this at all, given 8 tries". RL usually lifts pass@1 toward pass@8, which turns occasional success into
reliable success. That's case 1 of the toy, at scale.

## 5. Where this sits

| Stage | Signal | Teaches |
|---|---|---|
| Pretraining | next token of web text | language, facts, patterns |
| SFT | next token of curated conversations (assistant only) | the chat format, answering, tool calls |
| RL | 0/1 correctness of the final answer | getting answers right more reliably |
